# 現場筆記 FieldNotes：Wireframe 版型規格

> 所有設計風格（每套一個獨立的 Bootstrap 5 專案，純 HTML＋CSS＋少量 JS，唯一的編譯工具是 sass CLI）共用這份版型規格。
> 本文件規定**資訊架構與內容**：頁面與檔名、每頁的區塊與內容、元件、互動與狀態、RWD 的收合方式。**桌機欄數配置與區塊的排列構圖是建議**（wireframe 的排法），各風格依自己的排版語言決定（§0，2026-11-17 起）。
> **視覺風格**（配色、字體、圓角、陰影、圖片調性、裝飾）與**尺寸 token**（容器寬、內距、字級）由各風格自行決定，但要落在本文件給的範圍內（例如長文寬 680–720px、行高 ≥ 1.8）。
> **文案的唯一來源是 Notion**，已逐字整理在 [`../CONTENT.md`](../CONTENT.md)；Notion 沒寫的介面文字也統一在 CONTENT.md §10。wireframe 上的文字只用來對照位置。
> **圖片**清單在 [`../IMAGES.md`](../IMAGES.md)（17 張）。

- 來源：Notion「05-知識內容訂閱主題：現場筆記 FieldNotes」頁面內嵌的 `index.html`（<https://app.notion.com/p/3ef6ab47eb4880deba15e50c5092ec08>），原樣保存在 `index.html`
- 下載日期：2026-10-06（Notion 頁面最後編輯 2026-10-04）
- 對照檔：`index.html`（單一 HTML，5 個頁面區塊用 hash 切換，見 [README.md](./README.md)）、`screenshots/*.png`（1440 寬全頁截圖）
- 參考實作：`../../01-電商主題/01-luxury-style/`（同一套技術架構：多頁靜態 HTML、`templates/page.html`、`scripts/check-layout.mjs`、`scripts/generate-images.mjs`）
- 閱讀順序建議：〈0. 實作原則〉→〈1. 頁面清單〉→〈2. 全域規格〉→ 要做哪頁就看〈3〉的該頁 → 長文與付費牆看〈4〉〈5〉→ 元件狀態看〈6〉→ Guideline 看〈7〉→ 最後用〈10. 驗收清單〉自我檢查

## 0. 實作原則：哪些要照做、哪些可以發揮

| 必須遵守（3 套一致） | 可自由發揮（風格差異） |
|---|---|
| 10 個檔案與檔名（§1）、頁面之間的連結（§1.1） | 色彩、字體、字級比例、圓角、陰影、分隔線樣式 |
| 每頁的**區塊與內容**（§3）：有哪些區塊、區塊內的元件、欄位、文案、狀態、連結與示意資料 | **桌機欄數配置、區塊的排列構圖**（欄數與比例、區塊並排或堆疊、卡片或列表的呈現、側欄或篩選放哪、標題區的構圖）；區塊內的留白比例（但要維持閱讀層級） |
| 每個區塊包含的元件、欄位與狀態（§3、§6） | 區塊背景是否交替、深色區塊放在哪裡 |
| **文案逐字採用 CONTENT.md**，不改寫、不濃縮、不加形容詞 | 圖示樣式（一律從 Bootstrap Icons 選，§2.6 是建議） |
| 長文排版的硬性數值：內文最大寬 680–720px、內文行高 ≥ 1.8（§4） | 目錄放左或右、文章欄置中或靠左 |
| 付費牆的結構：漸層淡出 120–160px＋訂閱卡五件事，已訂閱者不渲染（§5） | 付費牆卡片、方案卡、狀態卡的視覺處理 |
| 狀態一律「圖示＋文字（＋顏色）」三重編碼，不能只靠顏色（§6） | hover、轉場等微互動 |
| 3 種角色在 `account.html` 的差異與切換方式（§3.05） | Guideline 的版面編排（但章節要齊，§7） |
| 圖片檔名、用途與畫面主體照 IMAGES.md | 圖片的色調、光線、後製（各風格 `STYLE`） |
| RWD 的收合順序、手機上的替代做法（各頁〈RWD〉） | 在規格外加入的裝飾性元素（不能取代文案或改變資訊層級） |

**2026-11-17 調整：欄數與構圖改成建議。** 使用者看了 01-typewriter 與 03-thinktank，覺得兩套「排版太像了，可以讓他們有些落差」。所以本文件規定的是**內容**（每頁有哪些區塊、區塊內的元件與欄位、文案、狀態、連結、示意資料），3 套一致；**排版組成**（桌機欄數、區塊的排列方式、卡片或列表的呈現、側欄放哪、標題區的構圖）由各風格依自己的排版語言決定，§3 寫的欄數與比例都是「建議（wireframe）」。**03-thinktank 採報刊排版**（報頭式頁首、12 欄網格與欄線、頭條／次條／短訊的標題階層，見該風格 README 的「排版語言」）；01、04 的既有頁面不重新排版。改排版時照這幾條：

1. 區塊在 HTML 的先後照 §3；兩個區塊並排時，排在前面的放左邊或上面（閱讀順序、Tab 順序和畫面一致）。
2. 不能為了排版刪掉、合併或改寫欄位、狀態與文案（文案仍逐字照 CONTENT.md）。
3. 可讀性與 RWD 優先：長文寬與行高（§4）、付費牆結構（§5）、觸控目標、任何寬度沒有水平捲軸；§3 各頁〈RWD〉寫的收合順序（哪個在上、什麼收進抽屜或下拉）照做，欄數是建議。
4. 新頁先看自己這套既有頁怎麼排，要像「這套風格」的一部分，而不是 3 套共用同一個版型只換顏色。
5. 風格實際的欄數與構圖寫進該風格 README（例如「排版語言」一節）與 Guideline「間距與格線」。

### 0.1 wireframe 標記怎麼讀

這份 wireframe 本身做得很完整（有配色、字體、甚至設計註解），**但它是資訊架構的草稿，不是任何一套風格的視覺規格**。它的奶油底＋墨褐字＋磚紅＋Noto Serif，原檔註解寫「對應風格 04 溫暖心靈慢讀」，但磚紅並不是 Notion 給 04 的焦糖駝色；**04 也要依 Notion 色系（燕麥灰白、焦糖駝色、柔暖灰）重新定義**，不要整組沿用 wireframe 的 token。

|---|---|---|
| 頁面最上方深色細列「FIELDNOTES DESIGN／知識內容訂閱服務 ‧ 五頁設計稿／顯示設計標註／斷點 xl · 1440px」 | 設計稿工具列 | **不做** |

### 0.2 設計稿狀態示意與切換器（本主題的共同做法）

訂閱平台的狀態很多（未訂閱／已訂閱、讀者／作者／管理員、四種訂閱狀態…），一頁只能呈現一種「目前狀態」。3 套統一用兩種方式呈現其他狀態：

1. **設計稿切換器**（頁面頂部，改變整頁的狀態）：只有兩處。
   - `article.html`：「未訂閱｜已訂閱」，預設未訂閱。網址 `article.html?view=subscribed` 直接開已訂閱。
   - `account.html`：「讀者｜作者｜管理員」，預設讀者。網址 `account.html?role=author`、`?role=admin`。
   - 外觀要和產品介面明顯區隔（例如虛線框、單色小字），並寫上標籤「設計稿狀態示意（非產品介面）」。用 `role="group"`、按鈕 `aria-pressed`。
   - 切換時用 `history.replaceState` 更新網址參數，重新整理後停在同一個狀態；網址有 `#錨點` 時，套用狀態後再捲到錨點（被隱藏的區塊要先顯示才捲得到）。
   - 建議的實作慣例（3 套一致，方便維護）：`<body data-view="unsubscribed|subscribed">`、`<body data-role="reader|author|admin">`；元素用 `data-show-view="subscribed"`、`data-show-role="author admin"` 標記，CSS 依 body 屬性隱藏不屬於目前狀態的元素。
2. **設計稿狀態示意區塊**（放在相關區塊下方，靜態並列其他狀態）：沿用 01 電商的 `.demo-state` 做法，以虛線與正式內容分開，標題寫「設計稿狀態示意：○○」。例如訂閱狀態的另外三種、付款的處理中／成功／失敗、空狀態。2026-11 補的 4 頁（§3.06～3.09）也只用這種方式，不另加設計稿切換器。

哪些狀態放在哪裡，見 §6.2 與 §9。

## 2. 全域規格

### 2.1 斷點與容器

wireframe 用 Bootstrap 5.3 原生斷點，**以 Bootstrap 斷點為準**：xs < 576、sm ≥ 576、md ≥ 768、lg ≥ 992、xl ≥ 1200、xxl ≥ 1400。

- 檢核寬度：**390／768／992／1200／1440／1920**（使用者要求每頁都看手機與 1920）。任何寬度都必須 `document.documentElement.scrollWidth === clientWidth`；橫向捲動只能發生在明確標示的容器內（比較矩陣、資料表、程式碼區塊、分頁籤）。
- 容器：wireframe 最大 1280px、左右內距 20px（≥ 992 為 32px）。風格可調，但 `$container-padding-x` 要 ≥ `$grid-gutter-width`，否則 `.row` 的負邊距會造成水平溢出。
- **長文閱讀寬（必須）**：文章內文、文章頁首、付費牆卡、文末區塊、Guideline 的長文示範，最大寬 **680–720px**，與容器寬無關；xxl 以上容器變寬時長文不跟著變寬。
- 寬窄層級：版面容器（最寬）＞ 長文閱讀欄 680–720 ＞ 方案頁首屏文字 ≈ 640 ＞ 取消對話框 ≈ 520。
- 區塊上下留白：wireframe 72px（< 992 為 52px）、緊湊區塊 44px；各風格自訂，但同類區塊要一致。
- sticky 元素（篩選側欄、文章目錄、方案頁訂閱摘要、個人頁側邊導覽、Guideline 目錄）的 `top` 要扣掉 sticky 頁首的高度（wireframe：頁首 68px＋28px 呼吸 = 96px），< 992 一律取消 sticky。
- 前台每頁是直向 flex、最小高度 100dvh，`<main>` 撐滿，頁尾貼底（沿用 01 電商的 `templates/page.html`）。

### 2.2 頁首（SiteHeader，每頁一份，與 `templates/page.html` 一致）

- sticky、底部分隔線，高度由風格決定（wireframe 68px）。內容放最寬的容器。
- 由左至右：

| 順序 | 元件 | 規格 | 顯示條件 |
|---|---|---|---|
| 1 | 品牌 | 「現場筆記」字標（可加 FieldNotes），連到 `index.html` | 永遠 |
| 2 | 主導覽 | 3 個連結：首頁、文章列表、訂閱方案 | ≥ lg（風格可改 ≥ md） |
| 3 | 搜尋 | 圖示按鈕 `aria-label="搜尋文章"`，點開搜尋框（placeholder：搜尋文章、作者或標籤），送出到 `articles.html` | 永遠 |
| 4 | 會員入口 | 頭像或人像圖示＋「我的現場筆記」（< lg 可只留圖示），連到 `account.html` | 永遠 |

- 表格的「由左至右」是 wireframe 的排法，也是 HTML（閱讀與 Tab）的順序。4 個元件每頁都要有，畫面上怎麼排由風格決定（例如 03-thinktank 的報頭式頁首：品牌置中在報頭列，導覽、搜尋、會員入口在下方的導覽列，捲動後只留導覽列）。
- **目前頁標示**：`index.html` → 首頁；`articles.html` → 文章列表（`aria-current="page"`）；`article.html`、`author.html` → 文章列表（只加 `active`，不加 `aria-current`）；`pricing.html` → 訂閱方案；`account.html` → 會員入口；`guideline.html`、`login.html`、`register.html`、`forgot-password.html` 不標示。改 `scripts/check-layout.mjs` 的對應：`article.html`、`author.html` 的目前頁是 `articles.html`（「文章內頁不加 `aria-current`」的判斷也要涵蓋 `author.html`）；`guideline.html` 與 3 個表單頁的 `expected` 是 `null`。
- **RWD**：< lg 顯示選單按鈕，點開用 Bootstrap Collapse 或 Offcanvas 顯示 3 個導覽連結＋會員入口；搜尋在小螢幕也要找得到（圖示按鈕展開搜尋列）。觸控目標 ≥ 44px。
- 不放「登入 / 註冊」按鈕：示意使用者陳柏諺已登入，每頁（含 2026-11 補的登入、註冊、忘記密碼頁）的頁首都照 `templates/page.html`，不另外改。登入頁從付費牆的「已經是訂閱者了？[登入]」進入，註冊頁從方案頁的「免費註冊」進入（§1.1）。

### 2.3 頁尾（SiteFooter，每頁一份）

- 品牌字標＋品牌說明（CONTENT.md §10.1）。
- 3 欄連結：**讀者**（瀏覽文章 `articles.html`、訂閱方案 `pricing.html`、我的收藏 `account.html#library`、訂閱狀態 `account.html#subscription`）、**作者**（申請成為作者 `account.html?role=reader#apply`、我的文章 `account.html?role=author#my-articles`、撰寫新文章 `account.html?role=author#editor`、內容數據 `account.html?role=author#analytics`）、**平台**（關於現場筆記、作者審核標準、退費與取消政策 `pricing.html#faq`、聯絡我們；沒有頁面的用不帶 `href` 的 `<a>`）。
- 版權列：CONTENT.md §10.1。
- **不放「設計稿」欄，不列出所有頁面**（含 Guideline）。

### 2.4 頁面標題區（首頁與文章內頁以外）

`articles.html`、`pricing.html`、`account.html` 的頁首結構一致：麵包屑 → H1 → 說明或控制項（選用），使用同一組間距，切換頁面時標題位置不跳動。麵包屑以「首頁」開頭，最後一項是目前頁（不是連結，`aria-current="page"`）。`pricing.html` 的 H1 與副標、切換開關在 wireframe 是置中（Notion：開門見山，不放品牌故事）；置中與否屬排版構圖（§0），風格可以改，例如 03-thinktank 把標題放在價目表的第一欄。`article.html` 的頁首是文章標題區（§3.03），麵包屑在它上方。

2026-11 補的頁面：`author.html` 同樣是麵包屑（首頁 ／ 文章列表 ／ 陳柏諺）→ H1（作者姓名，在作者資訊區裡，§3.08），麵包屑的位置與間距和 `articles.html` 一致。`login.html`、`register.html`、`forgot-password.html` 是表單頁，**不放麵包屑**（同 01 電商的登入、註冊），H1 放在表單卡裡（§3.06）。

### 2.8 JS 範圍（`js/main.js`，3 套一致）

2. **閱讀進度條**（article）：捲動時依文章主體（`#article-body` 到文末）計算百分比，更新頂端細條寬度與 `aria-valuenow`；沒有 JS 時顯示靜態 32%。
3. **字級調整**（article）：三段字級切換 `.prose` 的 class（行高同步），選擇可存在 `localStorage`（try/catch 包起來）。
4. **月／年切換**（pricing）：切到年繳時顯示「年繳一年省下 NT$ 360 ‧ 平均每月 NT$ 150」，並把被選中計費方式那張卡的按鈕升為強調樣式、另一張降為次要（§3.04）。
5. **作者文章狀態篩選**（account）：分頁籤「全部／已發布／草稿／已下架」用 `data-filter`，文章列用 `data-status`，同 01 電商「我的訂單」的做法。
6. （選用）收藏、追蹤作者的 `aria-pressed` 切換；閱讀模式切換；方案頁「確認付款」按下後依序顯示處理中 → 成功。

2026-11 補的 4 頁**不新增 JS**：表單用 `<form action>` 換頁（§1.1）、狀態用設計稿狀態示意、分頁是靜態頁碼。作者個人頁的「追蹤作者」沿用文章內頁作者卡的同一組 class 與屬性，風格已做了第 6 項的話會直接生效。顯示密碼切換需要 JS，本主題不做。

## 4. 長文排版規範（必須，寫進 Guideline）

Notion：「**內文最大寬度控制在 680–720px**，行高 1.8 以上，這組數值要明確寫進 Guideline 的長文排版規範。」以下是 3 套共同的規則；具體數值各風格在範圍內自訂，並寫進自己的 Guideline。

| 項目 | 規則 | wireframe 的值（參考） |
|---|---|---|
| 內文最大寬度 | **680–720px**，與容器寬度無關；文章頁首、表格、圖片、程式碼區塊都對齊這個寬度 | 720px |
| 每行字數 | 約 32–40 個全形字；超過 40 字眼睛回行會找錯 | 約 38 字 |
| 內文字級 | 16–18px（風格自訂） | 16.5px |
| 內文行高 | **≥ 1.8**；手機不下調 | 1.95 |
| 段落間距 | 約 1.2–1.5em | 1.35rem |
| 內文顏色 | 可比標題淺一階，降低長時間閱讀的壓迫，但對比 ≥ 7:1 為佳（至少 AA 4.5:1） | 比標題淺一階 |
| h2 | 文章內的大節；上距明顯大於下距（例如上 2.5–3em、下 0.75–1em） | 25px，上 2.75rem／下 0.9rem |
| h3 | h2 之下的小節，和 h2 要一眼分得出層級（字級、字重或字體至少差一項） | 19px 無襯線 700，上 2rem／下 0.6rem |
| 階層 | 一頁只有一個 h1（文章標題），內文只用 h2 → h3，不跳級 | — |
| 導言（lede） | 比內文大一階 | 18px／1.85 |
| 引言區塊 | 讓讀者在長文中間停一下：上下留白大於段落間距、和內文明顯區隔（左線、字體或字級） | 襯線 20px／1.72，左 3px 線，上下 2rem |
| 圖片與圖說 | 圖片滿閱讀欄寬、上下約 2rem；圖說小字、次要色，距圖約 0.6rem；`<figure>`＋`<figcaption>` | 13px／1.7 |
| 數據表格 | 數字欄靠右＋`tabular-nums`；合計列加粗或加底色；`<caption>` 寫表名與單位；窄螢幕在自己的容器內橫向捲動，**不撐破閱讀寬** | — |
| 項目清單／編號清單 | 行高同內文，項目間距比段落小 | li 間距 0.35rem |
| 行內程式碼 | 等寬字、淡底或細框，不要用連結色 | — |
| 程式碼區塊 | 等寬字、可橫向捲動、和內文明顯區隔（02 極客風的必備元素，3 套也都要有樣式） | 深色底、12px 圓角 |
| 分隔線 | 同一篇文章裡的話題轉折，上下約 2.4em | 1px 實線 |
| 免費預覽分隔線（編輯器） | 只出現在編輯器，讀者端渲染成付費牆 | 虛線＋強調底色＋拖曳把手 |
| 字級調整 Aa | 三段（例：16.5／18／20px），每段行高都 ≥ 1.8（字越大行高可略降） | 1.95／1.9／1.85 |
| 數字 | 大型單獨數字（價格、到期日）字寬由風格決定；表格與需要縱向對齊的數字用 `tabular-nums` | — |

- 中文沒有字間空白當落點，行高不足時眼睛會跳行；**手機行長只有約 20 字，也不要把行高壓低**（常見錯誤：手機改成 1.6）。
- 長文字體由風格決定（01 打字機可用等寬或打字機感字體、03 智庫可用報刊襯線、04 慢讀可用柔和的襯線或圓黑），但要確保中文字型有載入（Google Fonts 的 Noto Serif TC／Noto Sans TC 等），並在 Guideline 寫明。

## 5. 付費預覽牆（必須，寫進 Guideline）

Notion：「**不要硬切斷**——在免費段落的最後一段使用由上而下的漸層淡出（約 120–160px），讓讀者看得到文字正要變精彩，再壓上訂閱卡片。卡片需包含：已讀進度、價值訴求、兩種方案快速切換、主要 CTA、次要的登入入口。已訂閱者完全不會看到這個元件，這兩種狀態要在 Guideline 中並列呈現。」

| 項目 | 規範 |
|---|---|
| 漸層 | 由透明到頁面底色（或閱讀區底色）的線性漸層，高度 **120–160px**，覆蓋免費段最後一段並略往下延伸，讓殘句是「正在淡出」而不是「已消失」；`pointer-events: none`，不擋選字 |
| 殘句 | 免費段最後一段停在冒號「……我們一直沒算進去的那一項：」 |
| 卡片位置與層級 | 緊接在漸層下方，寬度＝閱讀欄寬；是**全站唯一壓在內容上的卡片**，可用浮起陰影或其他方式表現「擋住了下面的東西」 |
| 卡片內容（由上而下） | ①**已讀進度**：進度條＋「已免費讀完 32%」（必須帶數字）②**標題**「剩下的 4,600 字，需要訂閱才能繼續」③**價值訴求**（付費牆說明）④**兩種方案快速切換**：月費／年費兩個 RadioCard（年費帶「省下兩個月」標籤；預設選年費）⑤**主要 CTA**「訂閱並繼續閱讀」（滿寬，全卡唯一的主要按鈕）⑥**次要登入入口**「已經是訂閱者了？[登入]」⑦信任小字 ⑧替代入口「還沒想好？[先看看免費文章] ｜ [把這篇加入收藏，之後再讀]」（**只能是小字連結**，不能做成和 CTA 等重的按鈕） |
| 方案切換 | 兩個選項並排（≥ sm），手機上下堆疊；用 radio（`.btn-check`），選中狀態要明顯 |
| 已訂閱 | 整個元件**不渲染**（漸層、卡片、分隔線都沒有），文章接著往下；不放「你已訂閱」提示 |
| 未登入（只在 Guideline 示範） | 主要按鈕改「登入後訂閱」，下方小字 S01「登入後就能訂閱，註冊只要 30 秒。」 |
| 讀取失敗（選用） | 保留免費段＋重試連結 |
| 無障礙 | 漸層是裝飾（`aria-hidden`）；卡片用 `<section aria-labelledby>`；方案選項是真正的 radio |

Guideline 必須把「未訂閱（漸層＋卡片）」與「已訂閱（同一位置的正常內文）」**左右並列**。

## 7. 設計 Guideline（`guideline.html`）必含章節

Notion 規定 6 項：色彩、字級階層、間距、圓角陰影、元件狀態規範、RWD 斷點與 Do／Don't 對照；Notion 各區塊另外要求把長文排版、內文元素、付費牆兩態、訂閱狀態四態、角色三欄並列、編輯器元件集收進 Guideline。以下 12 節**都要有**（順序與合併方式可調，例如 01 電商把 RWD 與 Do／Don't 拆兩節）。所有示範都用頁面上**真的在用的 class 與元件**，不要貼截圖。

| 節 | 內容（必須） |
|---|---|
| 01 色彩 | 品牌色、中性色（底、卡片、線、文字層級）、狀態色（成功、警告、錯誤、資訊、中性）與**權限色**（訂閱限定、免費）；每個色票寫 hex、用途、對比度（文字色對底色，標 AA／AAA）；狀態色不得挪作裝飾 |
| 02 字級階層 | 標題（Display、H1、H2、H3）、卡片標題、文章列表標題、內文（介面）、長文內文、導言、引言、小字、價格與大數字；每級寫字體、字級、行高、字重、用途；寫明中文字型 |
| 03 長文排版規範 | §4 的每一項，寫出本風格的實際數值（內文最大寬、行高、段距、h2／h3 間距、引言、圖說、表格、程式碼、分隔線、Aa 三段），並放一段實際排版示範 |
| 04 間距與格線 | 間距尺度、容器寬與內距、區塊上下留白、**本風格實際的**各頁欄數配置（wireframe 的建議是首頁 7:5、列表 3:9、文章 8:4、結帳 7:5、個人頁 3:9、編輯器 8:4…，風格可以不同，§0）、sticky 偏移 |
| 05 圓角與陰影 | 圓角階層與用途；陰影（或不用陰影時的分層方式），付費牆卡、浮動工具列、插入選單、Modal 這類浮起層怎麼表現 |
| 06 元件狀態規範 | 按鈕層級與狀態、表單欄位 6 態、標籤、分頁籤、分段控制、**權限徽章**、狀態徽章、文章卡、主題卡、收藏／追蹤、頭像（照片／字首）；互動狀態對照表（hover／focus／disabled／錯誤） |
