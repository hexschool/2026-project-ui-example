螢光的使用限制

  • 只當底色，或放在深炭上當文字與圖示。在淺底上當文字只有 1.1:1（水泥灰）到 1.3:1（淺水泥），一律禁止。
  • 淺底上需要綠色字時，改用深青綠 $neon-deep；需要螢光感時，用螢光底塊＋深炭字（.tag-neon）。
  • 一個畫面的螢光面積約 5%，只留給五種用途：目前狀態（導覽目前頁、分頁籤、結帳步驟）、主要動作、現貨標籤、尺寸圖的標註、深色區塊的強調。
  • 其他地方一律用深炭或淺水泥：服務說明的圖示、流程的步驟編號、圖庫的張數牌、商品卡的編號條，都不上螢光。
  • 不做螢光漸層、發光陰影、螢光外框。唯一例外是焦點環：螢光內圈一定搭配深炭外圈。
  • 螢光不表示錯誤或警示；那是訊號紅與警示橘。

品名與標題的換行

標題已設定 text-wrap: balance；p、li、dd、label 用 text-wrap: pretty。品名另外要求：不從詞中間拆開。

虛線是欄寬邊界，示範欄寬 10rem，約等於手機 2 欄商品卡的標題寬度。

  • 斷點寫在 HTML：長品名在詞組之間插入 <wbr>，例如「自由拼裝<wbr>收納方塊」「懸浮感<wbr>洞洞板<wbr>壁面收納組 (免釘牆)」。畫面上看不到，文案仍然逐字。
  • .text-phrase（word-break: keep-all＋overflow-wrap: anywhere）只在空白與 <wbr> 換行；單一詞組比欄寬還長時才強制斷開。

  • 作法：margin-inline: -20px 加上 padding-inline: 20px，數值取自 $container-padding-x 的一半。class 版本加了 !important（和 Bootstrap 工具類別一樣），不會被頁面裡的 margin 簡寫蓋掉；頁面樣式裡要用時改用 mixin。

Do／Don’t 對照

「建議」是推薦做法，「避免」是常見的錯誤。範例都是真實的元件與類別；桌機左右並排，手機上下排列。

螢光只當底色，淺底上不寫螢光字

螢光在水泥灰上只有 1.1:1，幾乎看不見。要亮，就用螢光底塊加深炭字，或把螢光字放在深炭上。

相鄰的框共用一條線

兩個 2px 框直接疊在一起會變成 4px，粗細不一的線看起來像排版錯誤。外面一個框，裡面只畫分隔線。

同一組動作只有一個主要按鈕

主要按鈕有硬陰影和螢光字，反差最大。每顆都這麼醒目時，使用者得停下來判斷下一步。次要動作改用外框或文字按鈕。

陰影要硬，不模糊、不加圓角

柔和的模糊陰影與圓角是通用模板的樣子，會把粗框與銘牌的力道抵銷掉。重點面板用 4px 硬陰影，其他卡片不加。

尺寸寫成銘牌，不用形容詞帶過

租屋族最在意放不放得下。W／D／H 在列表上就要看得到，而不是點進詳情才找得到。

每張卡最多兩個標籤

標籤是資訊，不是裝飾。庫存一個、功能一個就夠了；標籤一多，商品圖被蓋住，重要的「剩幾件」反而找不到。

英文大寫只給代碼，標題直接說重點

標題上方的英文眉標、「·」串接、把一個詞換色、每個連結後面加箭頭，是模板常見的痕跡。這個風格的英文大寫只出現在品牌字與編號。

錯誤訊息說明怎麼修，不用喊的

反差大的風格更要注意語氣：錯誤訊息貼在欄位下方，說清楚缺什麼、該怎麼填，不用大寫、驚嘆號或錯誤代碼。

npm scripts

全部定義在 package.json。開發時開著 watch；交付前一律跑 build 再跑 check。

npm run watch
開發中：監看 scss/，存檔後約 1–2 秒重新編譯 css/style.css。不產生 source map；編譯出錯時，錯誤訊息會同時出現在終端機與頁面最上方，修正存檔後自動恢復。同一時間只開一個。
npm run css
編譯一次 css/style.css（不產生 source map），不含 vendor 複製。
npm run build
交付前用這個：先跑 vendor 再跑 css，確保 Bootstrap JS、圖示字型與 CSS 都是最新版。
npm run check
檢查 10 個頁面的共用區塊是否與 templates/page.html 一致，全部 ✓ 才算完成。
npm run vendor
只重新複製 Bootstrap JS 與圖示字型。npm install 時會自動執行（postinstall）。
npm run images
重新生成缺少的圖片，需要已登入的 codex CLI，只有換圖時才用；node scripts/generate-images.mjs --only hero,cta 只重做指定的圖。

開始工作

  1. 安裝

    $ npm install

    安裝 Bootstrap、Bootstrap Icons 與 Sass。postinstall 會把 bootstrap.bundle.min.js 複製到 js/vendor/、圖示字型複製到 css/fonts/。只想看畫面時不用安裝，直接打開 HTML 即可。

  2. 監看 Sass

    $ npm run watch

    存檔就重新編譯 css/style.css。同一時間只開一個 watch，兩個會互相覆寫。

  3. 打開頁面

    直接用瀏覽器開 index.html（或用編輯器的 Live Server 等任何靜態伺服器）。改完 SCSS 或 HTML，重新整理就看得到。

  4. 交付前

    $ npm run build
$ npm run check

    build 重新複製 vendor 並編譯一次 CSS；check 確認 10 個頁面的共用區塊都與範本一致，全部 ✓ 才算完成。

改頁首、頁尾或新增頁面

改頁首或頁尾

  • 沒有 include，頁首頁尾在每一頁都有一份完整的 HTML。先改 templates/page.html，再把同一段貼到 10 個 .html。
  • 每頁只允許這幾處不同：<title>、description、頁首目前頁的 .nav-link（加 .active 與 aria-current="page"；商品詳情標「商品一覽」但不加 aria-current）。
  • 改完執行 npm run check，有 ✗ 的頁面會列出哪一段不同。

新增頁面

  • 複製 templates/page.html，改檔名、<title>、description 與目前頁標示；首頁以外的頁面從 .page-header 開始。
  • 新增 scss/pages/_頁面.scss，在 main.scss 的各頁區加一行 @import；自訂 class 加頁面前綴，數值用 _variables.scss 的變數，不寫死色碼。
  • 新頁要從哪裡連進來（頁首導覽、其他頁的按鈕或連結），就在那些地方補上連結；改到頁首或頁尾時，同樣先改範本再同步所有頁面，最後跑 npm run check。check 是拿範本逐頁比對，只改頁面、沒改範本，全部都會 ✗。

互動與 JavaScript

互動一律用 Bootstrap 的 data-bs-* 屬性：collapse、dropdown、tab、carousel、offcanvas、modal，本頁目錄的目前章節也是 data-bs-spy="scroll"。不寫頁面專屬的 JS，HTML 裡不寫 inline script 或 onclick。我的訂單的狀態篩選由 js/main.js 切換顯示；數量加減、商品篩選、排序在設計稿裡是靜態畫面，正式串接時再接上資料。

js/main.js 的四個小功能

  1. 手機搜尋自動聚焦點放大鏡展開搜尋列後，游標直接放進搜尋框。
  2. 顯示密碼按鈕加 data-toggle-password="#password"，切換輸入框的 type 與 aria-pressed。
  3. 目前項目捲進畫面橫向捲動的分頁籤用方向鍵切換時，以及本頁手機目錄隨捲動換到新章節時（ScrollSpy 的 activate.bs.scrollspy），把目前項目捲進畫面。
  4. 篩選按鈕我的訂單的狀態列：清單加 id，按鈕群組加 data-filter-list="#ordersList"，按鈕寫 data-filter="待付款"（all 顯示全部），每筆訂單寫 data-status="待付款"；點按鈕時切換 .active、aria-pressed 與各筆的 hidden。
